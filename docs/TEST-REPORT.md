## 测试中发现并已修复的问题

1. **复习卡片自动翻回正面。** `useSettings()` 每次渲染都返回新对象，导致复习页不断重新加载队列。已改为稳定引用，E2E 3 加了回归检查。
2. **手机端词汇页筛选器占半屏。** 已改为在手机上收进「筛选」按钮。
4. **变位练习的题目会自己换掉。** 页面打开后设置才载入完，题目会被换成另一个人称，答得快的话会被判错。现在题目只在你点「下一个」时才换（这也是之前那个变位测试偶尔失败的原因，修复后连续 20 次通过）。
5. **邮件链接在已打开的页面里失效。** 路由会先改写网址，导致 Supabase 读不到链接；现在会先识别邮件链接并重新载入。
6. **变位练习占用了单词的每日新卡上限。** 变位卡的复习记录被算进主复习的「今天已学新卡」，导致单词提前到达上限。现在两者分开计数；新卡因上限被挡住时，复习页会说明并提供「今天再学 5 张」（只对当天有效）。单元测试按真实情况重现：13 个新词 + 2 张变位卡。
3. **按钮组被包在 label 里。** 阴阳性按钮、同义词等标签框的删除按钮都在 `<label>` 内，读屏软件会读错按钮名称；点同义词的标题文字时，还可能误删第一个标签。已改为分组容器。

## 已知问题与限制

- 打包体积约 600 KB（gzip 后 187 KB），首次加载后由 Service Worker 缓存。后续可拆分。
- 自动加 l' 的规则只处理元音开头的词；h 开头的词（l'homme / le héros）需要手动填冠词。
- iPhone 上必须「添加到主屏幕」使用，否则 Safari 可能在 7 天未使用后清除本地数据。设置页已有说明。
- 在 Safari / WebKit 上没有跑自动化测试：这里只有 Chrome 可用。部署后需要在你的 iPhone 上实测一遍。

## 自动更新（2026-11-17）

- 问题：从主屏幕打开的 iPhone app 是「恢复」而不是重新打开，旧版本会一直留着。
- 现在：每次切回前台（以及每小时）检查新版本；装好后立即切换，若正开着弹窗（可能在输入）则等下次切到后台再切换，不丢输入。
